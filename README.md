# Day-ahead electricity price forecasting (DE-LU)

Time series course project, Master of Science HES-SO (Lausanne), by Aladin and Léon.

## Question

How much do covariates (load, wind and solar forecasts, calendar) improve the forecast of next-day hourly prices in the Germany-Luxembourg bidding zone? And do foundation models used zero-shot beat classical statistical models?

| | Without covariates | With covariates |
|---|---|---|
| **Classical** | SARIMA | SARIMAX |
| **Foundation model** | TimesFM 3, Timestral | TimesFM 3 + cov., Timestral + cov. |

Baselines: naive D−1, naive D−7, `epftoolbox` reference naive, additive Holt-Winters.

## Protocol

- Forecast issued the day before auction gate closure, using only the information available at that time: past prices, published load, wind and solar forecasts, calendar. No actual covariate values.
- Rolling-origin evaluation, one day at a time, on the main test period (2026-04-01 → 2026-09-30, 183 days), same days for all models.
- Metrics: MAE, rMAE, RMSE, pinball loss, Diebold-Mariano test.
- Control period after the release of the foundation models (from 2026-10-16) to detect possible contamination of their training data.

The full protocol is described in [CLAUDE.md](CLAUDE.md).

## Results

All 10 models forecast the same 183 days × 24 hours of the main test (2026-04-01 → 2026-09-30) and the same 24 days of the control period (2026-10-16 → 2026-11-08). Details, tests and figures are in [`06_results.ipynb`](notebooks/06_results.ipynb).

| Model | MAE main test [EUR/MWh] | rMAE main test | MAE control [EUR/MWh] |
|---|---|---|---|
| Reference naive | 35.0 | 1.00 | 73.3 |
| Holt-Winters | 28.2 | 0.80 | 43.3 |
| SARIMA | 29.4 | 0.84 | 47.0 |
| SARIMAX | 17.9 | 0.51 | 23.6 |
| TimesFM 3 | 24.3 | 0.69 | 27.7 |
| TimesFM 3 + cov. | 14.4 | 0.41 | 18.8 |
| Timestral | 22.8 | 0.65 | 28.2 |
| **Timestral + cov.** | **13.0** | **0.37** | **18.7** |

The two-way table of the research question (MAE on the main test, EUR/MWh):

| | Without covariates | With covariates | Covariate gain |
|---|---|---|---|
| Classical (SARIMA → SARIMAX) | 29.4 | 17.9 | −39 % |
| TimesFM 3 | 24.3 | 14.4 | −40 % |
| Timestral-209M | 22.8 | 13.0 | −43 % |

- **Covariates** (load, wind and solar forecasts, non-working day) reduce the MAE by about 40 % in every family. The gain is significant in all three families (multivariate Diebold-Mariano test, p < 1e-28), and it is largest on windy days and negative-price hours.
- **Foundation models vs course models**: used zero-shot, TimesFM 3 and Timestral beat the classical model with the same information, by 17 to 22 % without covariates and by 19 to 27 % with them. Timestral + cov. is the best model overall (significantly better than SARIMAX, p ≈ 1e-18). Timestral is ahead of TimesFM 3 with absolute errors, but not robustly (not significant with squared errors or on the control period).
- **Covariates matter more than the model family**: SARIMAX beats both foundation models when they only see prices.
- **No model forecasts the extremes**: spikes are under-forecast and deep negative prices are not deep enough. The missing information (gas and CO₂ prices, system flexibility) is a limitation of the protocol.
- **Contamination test**: no signal. Relative to SARIMAX, the foundation models are not worse on the control period, which is after their release, than on the main test.

## Structure

```
notebooks/
  01_download.ipynb     # ENTSO-E → preprocessing → data/dataset.parquet
  02_exploration.ipynb  # exploratory analysis, SARIMA order selection
  03_baselines.ipynb    # naives, Holt-Winters
  04_sarima.ipynb       # SARIMA, SARIMAX
  05_foundation.ipynb   # TimesFM 3, Timestral
  06_results.ipynb      # tables, DM tests, detailed analyses
src/
  config.py             # protocol periods and parameters
  data.py               # loading, history / future covariates split
  evaluation.py         # common rolling loop, metrics
  foundation.py         # TimesFM 3 / Timestral wrappers, context and covariate arrays
tests/                  # unit tests of src/ on synthetic data
figures/                # final figures
slides/                 # presentation (build_slides.py → presentation.pptx)
```

## Reproduce

```bash
uv sync                      # install the environment
uv run nbstripout --install  # strip notebook outputs on commit
cp .env.example .env         # then set ENTSOE_API_KEY
uv run pytest                # unit tests of the evaluation core
```

Then run the notebooks in order. To rebuild the slides from the figures: `uv run --with python-pptx python slides/build_slides.py`. The data comes from the [ENTSO-E Transparency Platform](https://transparency.entsoe.eu) and is not redistributed in this repository: `01_download.ipynb` downloads it.
